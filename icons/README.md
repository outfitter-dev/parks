# Designing a custom Parks icon

Start with an actual interface need. Search the maintained [Solar catalogue](https://solar-icons.dev/) for the object, action and synonyms. Record the nearest match and where it fails in context. If an existing icon works, use it and close the study with that decision.

## Make one Linear master

1. Copy the [trail cairn study](studies/trail-cairn/) to a directory named for the concept. Replace the brief, artwork, review title and record. Put the intended product placement, size and likely misreading in the brief. Choose a Solar neighbor with similar silhouette or density. Keep its URL, author and license.
2. In Paper, lay out the neighbor, a concept sketch and candidates side by side at actual size. Use Paper’s Quiver integration for alternatives or send the same prompt and reference images to Quiver directly. Label each reference by role. For style transfer, describe what must survive from the concept (e.g. an open gate), and which traits come from Solar (weight, spacing and endpoints). Record the concept source and adaptation rights before uploading or reusing someone else’s drawing. A redraw still needs provenance. [Paper vector editing](https://paper.design/docs/svg) · [Paper generation support](https://paper.design/build-log) · [Quiver reference inputs](https://docs.quiver.ai/developers/models/text-to-svg)
3. For agent-assisted work at the desk, connect the local Paper MCP and confirm the open file. Remote MCP is an alternative for a cloud agent with access to the design. Either route should end with an editable SVG exported into the study. Keep a link to the Paper frame and the actual generator/model when visible. Hand drawing uses the same review path. [Paper MCP setup](https://paper.design/docs/mcp)
4. Clean the selected candidate. This first Parks profile uses a 24 × 24 viewBox, live 1.5 px strokes, round joins and caps, and inherited currentColor. Store the drawing as paths directly under the root with the shared attributes in the example. Rebuild expanded outlines as editable centerlines if needed. The narrow file format makes the trial easy to inspect. Solar exports can use other representations. Check the maintained catalogue’s style-specific expectations before adding support for another style. [Solar contribution guidance](https://solar-icons.dev/docs/v2/community/contributing)
5. Run `python3 icons/check-linear.py icons/studies/<name>/linear.svg` from the repository root. Open the study’s review.html in a browser. The checker verifies markup and shared styling. Inspect actual rendering for broken geometry, clipping, tangent collisions and gaps. In Paper or the target interface, compare the icon beside its reference at 16, 20 and 24 px on both surfaces. Ask someone to identify the icon without its label, then try it with the real UI label. Record the result and any edits.
6. Keep the selected SVG, meaningful rejected alternatives and a short chronological decision record in Git. Each decision should name the candidate, observation at a specific size or in context, change and reviewer. Link the commit, Paper frame or issue when it adds evidence. Record authorship, third-party inputs, generator involvement, attribution and disposition (study, approved for Parks, retired, or upstream proposal). Promote an approved master through the Parks package once its asset entry point lands. The study path is for review.

## Learn across icons

When the same correction recurs, link the studies and write the proposed rule with its counterexample. For example, “both gaps closed at 16 px” is testable against later drawings. “Make it more Solar” gives the next designer little to work with. Promote a measurable rule to the checker only when it applies across accepted icons. Keep optical and semantic judgments in the review record. These decisions and original editable masters can seed an Outfitter family later.

## Propose artwork upstream

For the maintained solar-icons.dev catalogue, open an icon request describing the gap and wait for agreement on scope before beginning contribution artwork. Share editable Linear SVG and a preview in that issue; Paper is sufficient. Disclose references, adaptations and AI assistance and confirm acceptability with maintainers. After Linear approval, develop the five remaining styles and review them together. Maintainers integrate accepted vectors into Figma. Their policy distinguishes original 480 Design artwork and corrections (CC BY 4.0) from accepted new original icons (MIT with author credit). Preserve source-specific notices for derivative work.
